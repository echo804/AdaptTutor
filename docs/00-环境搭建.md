## 2. 服务常驻内存预算（16GB 硬约束）

| 组件 | 预算 | 说明 |
|---|---|---|
| PostgreSQL | 1.5GB | `shared_buffers = 256MB` 起步，按需调整 |
| FastAPI (api) | 0.5GB | 单 worker（异步 IO 足够） |
| Next.js (web) | 0.5GB | 生产模式单实例 |
| 前端 dev server | 0.5GB | 仅开发期占用 |
| 系统 + Docker Desktop（WSL2） | 3-4GB | 含 WSL2 常驻开销 |
| **合计** | **6-7GB** | 预留 9-10GB 余量 |

**砍组件即省内存**（对比 V1.0 方案）：
- Neo4j（JVM 常驻 3-5GB）→ PostgreSQL JSONB：**省 ~4GB**
- Qdrant（~0.5GB）→ 标签过滤：**省 ~0.5GB**
- Celery worker（~0.3GB）→ FastAPI 后台任务：**省 ~0.3GB**
- Redis（~0.2GB）→ 后置：**省 ~0.2GB**

这是本方案能在 16GB 机器上落地的根本原因。**每周检查一次实际内存占用**（任务管理器或 `Get-Process`），若总占用持续 > 12GB，优先砍前端 dev server 与调整 PG 缓存参数。

## 3. 开工整改清单（按顺序执行，全部完成后才允许写代码）

### 3.1 启动 Docker Desktop
1. 启动 Docker Desktop（开始菜单），等待引擎就绪。
2. 验证：`docker ps` 能正常返回（无连接错误）。
3. 设置开机自启：Docker Desktop → Settings → General → "Start Docker Desktop when you sign in"。
4. 确认后端为 WSL2：Settings → General → "Use the WSL 2 based engine"（本机已装 Ubuntu，直接可用）。

### 3.2 迁移 Docker 数据目录到 D 盘（C 盘只剩 42.5GB，必须做）

> ✅ **2026-08 实测结论：本机数据目录已在 D 盘，无需迁移**。docker-desktop WSL 发行版 BasePath = `D:\docker\wsl\main`（注册表 Lxss），`settings-store.json` 的 `CustomWslDistroDir` 已配置为 `D:\docker\wsl`；C 盘剩余 42GB 不受 Docker 影响。

（以下为原计划步骤，仅当换机/重装时参考：Docker Desktop → Settings → Resources → Advanced → Disk image location 改到 D 盘；应用后自动迁移 WSL2 vhdx。）

### 3.3 固定 Python 版本（3.12）
- 本机已装 Python 3.12（`C:\Users\<user>\AppData\Local\Programs\Python\Python312`），**无需重装**。
- 项目统一用 `py -3.12` 创建虚拟环境：
  ```powershell
  py -3.12 -m venv .venv
  .\.venv\Scripts\Activate.ps1
  python --version   # 确认 3.12.x
  ```
- 在 `pyproject.toml` 中声明 `requires-python = ">=3.11"`，CI/本地均以 3.12 为准。
- 系统默认 3.10 与 anaconda 3.13 保持不动，项目隔离在 `.venv` 内，互不干扰。

### 3.4 对齐 Node 版本（Next.js 14）

> ✅ **2026-08 已完成**：nvm-windows 1.2.2 安装于 **D:\nvm**（避开 C 盘与中文用户名路径问题），`NVM_HOME=D:\nvm`、`NVM_SYMLINK=D:\nodejs`（用户级环境变量）；`nvm install 20` + `nvm use 20` 后 node = **v20.20.2**。新终端需重新打开生效。

（原方案：Next.js 14 官方支持 Node 18.17+ / 20；安装 Node 20 LTS 推荐 nvm-windows；项目根 `.nvmrc` 内容 `20`。）

### 3.5 建立备份目录
- 创建 `D:\AdaptTutorBackup`（pg_dump 每日全量落点，保留 7 天）。

## 4. 配置管理

### 4.1 配置来源
- 全部配置走 `.env`（仓库内提供 `.env.example`，实际 `.env` 被 `.gitignore` 忽略）。
- 启动时执行配置校验（fast fail）：缺失/非法配置直接拒绝启动，不静默降级。

### 4.2 配置项清单（草案）

| 变量 | 说明 | 示例 |
|---|---|---|
| `DATABASE_URL` | PostgreSQL 连接串 | `postgresql+asyncpg://adapt:xxx@localhost:5432/adapttutor` |
| `LITELLM_API_KEYS` | 系统级 key（各供应商；仅开发/测试/内部用途，**不作为用户兜底**） | 逗号分隔或 JSON |
| `API_KEY_ENC_KEY` | 用户 key 加密密钥（Fernet，04 2.9） | `Fernet.generate_key()` 输出 |
| `JWT_SECRET` | JWT 签名密钥 | 随机长字符串 |
| `JWT_EXPIRE_MINUTES` | JWT 过期时间（分钟） | `720` |
| `INVITE_ONLY` | 是否仅邀请码注册 | `true` |
| `MODEL_ROUTING` | 分层路由配置（诊断/出题/对话各用哪家模型） | JSON |
| `DOMAIN_PACK_PATH` | 领域包目录路径 | `./domain_packs` |
| `ACTIVE_DOMAIN_PACK` | 当前激活的领域包 id | `junior_math_eq_ineq` |
| `PURITY_THRESHOLD` | 引导纯度阈值（评估层） | `0.9` |
| `LOG_LEVEL` | 日志级别 | `INFO` |
| `BACKUP_DIR` | 备份目录 | `D:\AdaptTutorBackup` |

### 4.3 密钥管理规则（双轨，对齐 04 v0.4）
- **系统级 key（`LITELLM_API_KEYS`）**：仅存 `.env`（开发/测试/系统内部用途，**不作为用户兜底**）；不入库、不进日志、不提交 Git。
- **用户级 key（`user_api_keys` 表）**：用户自配，**Fernet 对称加密入库**；加密密钥 `API_KEY_ENC_KEY` 存 `.env`（与 key 本身分离）。界面仅掩码显示（`sk-****abcd`），不可回读。
- 日志模块对 key 做脱敏（打码中间段）——系统级与用户级均适用。
- `.env.example` 用占位符（`sk-xxx`），真实 key 仅存在于本机 `.env`；`API_KEY_ENC_KEY` 必须妥善保管（丢失则所有用户 key 无法解密）。

## 5. 环境分层

| 环境 | 用途 | 形态 |
|---|---|---|
| local | 日常开发 | 本机 `.venv` + Node dev server；PG 用容器（`docker-compose.local.yml` 的 postgres 服务） |
| staging | 联调/冻结前验证 | 本机独立 Docker Compose 栈（独立端口 + 独立卷，如 `:5433`） |
| release | 可发布形态（本地） | 镜像 tag 固定 + compose 文件锁定，可整体回滚 |
| prod（云部署） | 邀请制公开使用（04 2.8） | `docker-compose.prod.yml`：nginx + HTTPS + 域名 + 云备份；**上云前置项**完成后启用（登录安全强化/HTTPS/云备份） |

> 说明：local 与 staging 的数据卷必须物理隔离，避免开发数据污染验证数据。云部署（prod）本期不实现，仅约定结构（04 v0.3）。

## 6. 常见故障排查

| 现象 | 排查步骤 |
|---|---|
| `docker ps` 连接失败 | Docker Desktop 未启动；或引擎还在启动中；或 WSL2 后端异常（`wsl --status` 检查） |
| PG 连不上 | 容器是否 up（`docker compose ps`）；`DATABASE_URL` 端口/密码是否匹配 |
| 内存占用过高 | 对照第 2 节预算表逐组件排查；优先停 dev server / 调小 PG 缓存 |
| LLM 调用失败 | 检查 `.env` key 是否有效、余额；LiteLLM 是否配置了备用模型路由 |
| 中文乱码 | PowerShell 下确认 `[Console]::OutputEncoding = UTF8`；文件统一 UTF-8（无 BOM） |
