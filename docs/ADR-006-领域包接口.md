# ADR-006：领域包接口（schema 校验 + 文件目录 + 零改引擎接入）

> 状态：**已接受（2026-08）** · 关联：docs/03 §2.2、docs/02 M6、`app/domain/`

## 背景

产品定位是"通用学习引擎 + 领域包"（04 决策 1）：**引擎领域无关，学科内容以领域包接入**。新学科接入必须"零改引擎代码"。当时候选：数据库内嵌图谱 vs 文件目录领域包。

## 决策

**文件目录领域包 + Pydantic schema 校验**（`app/domain/`）：

```
domain_packs/<pack_id>/
├── pack_manifest.json        # 元信息（id/subject/version）
├── knowledge_graph.json      # 图谱（GraphNode/GraphEdge：难度/重要度/错误模式/前置依赖）
├── questions.json            # 题库（Question：题型/知识点标签/选项错误模式/解题步骤→节点映射）
├── diagnostic_rules.json     # 诊断规则（BKT 参数/终止规则）
└── assessment_config.json    # 评估配置（纯度阈值等）
```

关键点：
- **`DomainPack` 是唯一契约**：`loader.load_pack()` 加载 + `Pydantic.model_validate` 校验（fast-fail，非法即拒绝）
- **三种接入方式**，同一 schema：手写目录（模板）、AI 生成（`new_pack_ai.py`）、可视化编辑器（M6，产出同一目录）
- **图谱存储可替换**：引擎只依赖 `load_pack()` 返回的 `DomainPack`，不关心 JSON 来自文件/PG/编辑器

## 为什么

1. **零改引擎**：新领域 = 新增目录，引擎零改动（M4r18 验证"图谱数据全部来自领域包，无硬编码"）
2. **校验前置**：schema 校验保证坏包进不来，引擎不会遇到脏数据
3. **版本可控**：pack_manifest 带 version，可演进
4. **编辑器友好**：固定 schema 是可视化编辑器（M6）的稳定输出契约

## 后果

- 正面：领域无关达成、接入门槛低（手写/AI/编辑器三路）、校验严格
- 代价：需维护 schema 演进（加字段时向后兼容）；AI 生成质量需人工审阅（`export_pack_review.py` 审阅清单）
- 演进：领域包可打包发布（市场/共享），schema 稳定是前提

## 验证

- 内置领域包 1（初中数学·方程与不等式）全量加载通过（F1）
- 新增领域包操作手册已文档化（docs/新增领域包操作手册.md）
- 用户自助创建领域（M4r8d：上传素材 → AI 生成 → 发布）复用同一 schema（138 tests passed）
