# ADR-001：对话控制用自研四态状态机（弃 LangGraph / 通用 Agent）

> 状态：**已接受（2026-08）** · 关联：docs/02 §2 M2、docs/03 §4、docs/04 决策 5

## 背景

对话是产品的核心交互（苏格拉底式辅导），需要**精确控制"不直接给答案"**这一硬约束。当时候选：自研状态机 vs LangGraph vs 通用 Agent 编排。

## 决策

**自研四态状态机**（`engine/state_machine/`：`states.py` + `state_machine.py` + `frustration.py`），四态：探明（elicit）→ 识别错误（identify）→ 最小提示（hint）→ 变式验证（verify）。

配套：
- **输出自检层** `output_sanitizer.py`：AI 输出经规则过滤，拦截"直接给答案"
- **拒答检测** `refusal_detector.py`：识别 AI 拒绝回答场景，触发重试/降级

## 为什么

1. **确定性**：状态转移矩阵可单测全覆盖（F2 实测矩阵测试全绿），可回滚；LangGraph 是图编排框架，引入后测试与调试成本高
2. **精确控制纯度**：自检层 + 状态机双重保证引导纯度 ≥ 90%（F2 实测 100%）
3. **领域无关**：状态机不绑定任何学科，领域包只提供数据
4. **单机规模**：无分布式诉求，Celery/LangGraph 等属于过度设计（04 决策 5）

## 后果

- 正面：纯度硬指标达成、测试完备、可回滚
- 代价：非通用 Agent，无法处理"自由对话"类需求——边界由 02 §1.2 Must Not 明确（"本项目对话是有限状态机，非通用 Agent"）
- 未来若需扩展：状态机接口稳定，可在状态内扩展子流程，不推翻现有架构

## 验证

- 状态转移矩阵单元测试全绿（F2）
- 引导纯度回归集 20 题 100%（F2）
- 挫败感检测规则引擎（`frustration.py`）随 M2 落地
