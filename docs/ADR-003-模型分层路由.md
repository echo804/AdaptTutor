# ADR-003：LLM 模型分层路由（角色路由 + 按用户 key + 三层降级）

> 状态：**已接受（2026-08）** · 关联：docs/01 5、docs/04 2.9、docs/03 §5.0

## 背景

系统有多个 AI 角色：诊断（diagnostic）、辅导讲解（tutor）、出题（generate）、判题（judge）。各角色对模型要求不同（出题可便宜些，讲解要更强）。同时必须支持**按用户自配 key**（04 决策：强制自配，无全局兜底）。

## 决策

**四角色分层路由**（`engine/llm_gateway/routing.py`）：

1. **角色 → 模型映射**：`MODEL_ROUTING` JSON 配置 `{"diagnostic": "provider/model", "tutor": ..., "generate": ...}`（当前默认：diagnostic/tutor 用 deepseek-v3，generate 用 qwen-turbo）
2. **key 解析优先级**：用户自配 key → 系统级 LITELLM_API_KEYS（仅开发/测试，`sk-xxx` 占位视为无效）
3. **上下文覆盖**：设置页可对某角色选模型（如百炼免费额度模型下拉，`override` 优先于 routing）

配套三层降级（`degradation.py` + `gateway.py`）：
- 第一层：主模型 → 备用模型（同供应商切换）
- 第二层：不同供应商兜底
- 第三层：**mock 降级**（无 key/全部失败时不中断会话，返回受控占位）

## 为什么

1. **成本归各用户**：不配 key 就无法用 AI（后端 403 + 前端置灰，M4r17/M4r18 验证）
2. **成本优化**：出题/判题用便宜模型，讲解用强模型，按角色分流
3. **降级不中断**：LLM API 不稳定时（断网/超时/限流）会话不崩，降级成功率目标 ≥ 99%（03 §3.2，故障注入验证）
4. **LiteLLM 统一接口**：多供应商一个调用接口，切换无侵入

## 后果

- 正面：成本可控、降级健壮、按用户 key 强制（符合 04 平权/无计费原则）
- 代价：需维护 MODEL_ROUTING 配置；未配 key 用户无法体验 AI（这是设计意图）
- 演进：模型微调后（04 后置项）只需改 routing 映射，评估层已沉淀标注数据

## 验证

- 无 key 创建会话 → 403「未配置 LLM API key」（M4r18 实测）
- 降级路径：gateway/degradation 实现三层，故障注入属联调周范畴
- 前端设置页可配 4 家供应商 + 百炼模型偏好（M4r10 前已实现）
