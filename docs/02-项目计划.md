# 02-项目计划

> 范围、里程碑、质量标准与风险。**原则**：不设缓冲期——超期先砍范围（对照三层表），不延冻结点。

---

## 1. 范围边界：三层细化

### 1.1 第一层：本期必须做（Must）

**引擎（领域无关）**
- 苏格拉底四态状态机 + 输出自检层
- 诊断引擎（KST 简化 + BKT 参数化）
- 路径规划（拓扑序 + 权重）与错题溯源（依赖链回溯）
- 遗忘调度（曲线可配置 + 变式题生成）
- 评估层（引导纯度检测 + 回归测试集框架）
- 持久化（PG 全量）、LLM 网关（LiteLLM 分层路由 + 按用户 key）、结构化日志（trace_id）
- 领域包加载器（schema 校验 + 运行时导入）

**账号与认证（对齐 04 v0.3/v0.4）**
- 登录/注册：JWT 认证 + 邀请码注册（`invite_codes` 表，CLI 脚本生成邀请码）
- 用户 API key 管理：`user_api_keys` 表，Fernet 加密存储，设置页配置（掩码显示）
- 未配 key 限制：AI 功能（诊断/辅导/复习/判题）需有效 key；未配 key 仅可浏览页面 + 简单非 AI 交互

**领域包 1（内置）：初中数学·方程与不等式**
- 知识图谱 30-50 节点（难度/重要度/错误模式/前置依赖）
- 题库 100+ 题（知识点标签/选项错误模式/解题步骤→节点映射）
- 诊断初始题库 + 评估配置（BKT 参数、纯度阈值）

**前端（最小可用）**
- 对话界面（KaTeX 公式渲染）、图谱可视化（React Flow：掌握度着色/溯源高亮）
- 登录页、设置页（API key 配置/改密码/账号）、诊断报告页 + 学习进度仪表盘

**领域编辑器（M6，排期 A）**
- 可视化领域编辑器：图谱节点/边编辑（React Flow）、题目录入、schema 校验、导入导出
- 验收：编辑器产出的领域包能被引擎"零改代码"消费（与手写目录走同一 schema）

**运维完备**
- Docker Compose 一键启动（`docker-compose.local.yml`）、.env 配置校验（fast fail）、健康检查
- Alembic 数据迁移、每日备份（pg_dump → D 盘，保留 7 天）、恢复演练

### 1.2 第二层：明确不做（Must Not）

- 多学科/全科覆盖（只做内置领域包 1；其他领域经领域编辑器或目录接入，见 M6）
- 移动端原生应用、多模态（语音/白板/手写识别）
- 角色分级 / 管理员后台（邀请制多用户，全部平权为学习者）
- 多租户隔离与计费（免费开放，无商业化）
- 自训练模型、本地推理（LLM 全走 API）
- 真实成绩提升的因果证明（无学校对照数据；效果指标见第 3 节）
- 分布式/高可用（单机目标，不做集群/负载均衡）
- 通用 Agent 编排（LangGraph 等）——本项目对话是有限状态机，非通用 Agent

### 1.3 第三层：预留后置（Later，接口预留不实现）

| 后置项 | 触发条件 | 预留方式 |
|---|---|---|
| 新领域包接入 | 领域包 1 闭环验证通过后 | 两种方式：可视化编辑器（M6 产出）/ 手写目录，同一 schema 校验，零改引擎 |
| 向量检索（pgvector） | 题目规模 > 5000 或语义检索需求 | question_bank 预留 embedding 字段；现用标签过滤 |
| Redis + 队列 | 后台任务阻塞 API / 需多 worker | 任务提交/查询统一抽象，状态持久化 PG |
| 可观测性面板（LangFuse/OTel） | 需要跨服务追踪或可视化评估 | 评估数据已在 PG，可平滑导出 |
| 多语言/语音 | 前端交互需要 | 对话协议为纯文本，可扩展 |
| 模型微调 | 引导纯度长期不达标 | 评估层已沉淀标注数据，可直接作微调语料 |
| 登录安全强化（防爆破/验证码/密码重置） | **上云前置项**（云部署公开前必做） | JWT 认证已就位，接口预留 |
| 云部署（HTTPS + 域名 + nginx 反代 + 云备份） | **上云前置项** | compose 拆 local/prod 结构，本期仅实现 local |
| 家长/老师报告（PDF 导出） | 出现老师/家长角色需求 | 评估数据已在 PG，可平滑导出 |
| 移动端响应式强化 | 上云后视用户设备分布 | Tailwind 响应式基础预留 |
| PWA / Electron / Tauri 加壳 | 功能稳定后按需选择 | 前后端分离，加壳只包前端，不锁死 |

> 完整后置清单与触发条件见 [[04-需求决策记录]] 第 6 节（本文档为摘要）。

### 1.4 边界治理规则

任何"顺手加功能"的冲动：先对照三层表——不在第一层的，一律记入第三层或拒绝。**第三层的东西在触发条件满足前不允许提前引入。**

## 2. 里程碑与实施计划（14 周）

**节奏约定**：
- 每个阶段结束设**冻结点 Fx**：功能冻结，之后只修缺陷、不再加功能。
- **第 8 周为全系统联调周**：前后端 + 引擎 + 评估层端到端联调、数据一致性验证、性能基线建立。
- M6 结束设**发布冻结**：仅允许 P0 缺陷修复，准备 v1.0 发布。

| 阶段 | 周期 | 内容 | 验收（对应硬指标） | 冻结点 |
|---|---|---|---|---|
| **M1 引擎骨架** | W1-2 | 项目脚手架；PG schema + Alembic；领域包加载器；诊断引擎（KST+BKT 简化）；领域包 1 最小集（30 节点 + 100 题）；命令行跑通"诊断→薄弱点→路径" | 图谱来自领域包而非硬编码；诊断 10-15 题收敛 | **F1（W2 末）** |
| **M2 辅导引擎** | W3-5 | 四态状态机 + 单元测试全覆盖；输出自检层；引导纯度评估 + 回归测试集（20 题）；挫败感检测规则引擎 | 引导纯度 ≥ 90%；状态转移矩阵测试全绿 | **F2（W5 末）** ✅ 已完成：引导纯度 100%（20/20）、矩阵单测全绿、辅导闭环可跑通 |
| **M3 溯源与调度** | W6-7 | 错题溯源（步骤→节点映射 + 依赖链回溯）；遗忘调度 + 变式题生成；PG 全量持久化 + 每日备份脚本 | 溯源一致率 ≥ 70%；会话恢复 100%；变式题可用 ≥ 80% | **F3（W7 末）** ✅ 已完成：溯源一致率 100%、会话恢复 100%、变式可用率 100%（235/235）、每日备份脚本就绪 |
| **联调周** | W8 | 端到端联调；数据一致性（事件流与掌握度一致）；性能基线；长会话压力测试 | P95 ≤ 5s；20-30 分钟连续辅导无崩溃 | — |
| **M4 前端与运维** | W9-10 | 对话界面（KaTeX）；图谱可视化；登录页/注册（邀请码）与设置页（key 配置）；诊断报告 + 仪表盘；Docker Compose 一键启动；健康检查；部署文档 | `docker compose up -d` 一键起全套；登录/注册可用；仪表盘可展示真实数据 | **F4（W10 末）** |
| **M5 真实使用验证** | W11-12 | 连续 2 周真实学习使用；收集数据修复缺陷；修正 ≥ 3 处问题；补 ADR 与领域包接入指南 | 见 3.3 落地验证硬指标 | **F5（W12 末）** |
| **M6 可视化领域编辑器** | W13-14 | 图谱节点/边编辑（React Flow）；题目录入表单；schema 校验与导入导出；领域包写入 API | 编辑器产出的领域包被引擎"零改代码"消费（与手写目录同一 schema 校验） | **F6（W14 末）→ 发布冻结 → v1.0** |

**时间账**（对比 V1.0 的 15 周）：砍 Neo4j/Qdrant/Celery/白板净省约 3 周，主线 12 周紧凑排期；按 04 排期 A 新增可视化编辑器 M6（W13-14，约 2-3 周），总周期 14 周。**超期处理：第一反应是砍范围（对照三层表），不是延后冻结点。**

## 3. 质量标准：量化硬指标

> 每一项都必须可测量、可验证，不达标即该阶段未完成。验收在冻结点执行。

### 3.1 功能质量

| 指标 | 目标值 | 测量方式 | 对应模块 |
|---|---|---|---|
| 引导纯度（不直接给答案） | ≥ 90% | 回归测试集 20 题 × 自检层判定 | 状态机 + 评估层 |
| 诊断收敛 | 10-15 题内定位根因节点 | 人工标注验证集（20 场景）根因命中 ≥ 70% | 诊断引擎 |
| 状态机完整性 | 四态流转无死锁、无非法跳转 | 单元测试覆盖全部状态转移 | 状态机 |
| 会话恢复 | 100% | 重启服务后会话/掌握度完整恢复 | 持久化 |
| 变式题可用性 | ≥ 80% | 生成 50 题人工抽检：可解 + 知识点匹配 | 遗忘调度/出题 |
| 错题溯源正确性 | 根因路径一致率 ≥ 70% | 20 个标注错题场景 | 图引擎 |

### 3.2 系统质量

| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 稳定性 | 20-30 分钟连续辅导无崩溃/状态错乱 | 长会话压力测试 |
| LLM 降级 | API 失败自动切换备用模型，降级成功率 ≥ 99% | 故障注入（断网/超时/限流） |
| 可观测性 | 100% 会话可凭 trace_id 回溯 | 日志审计抽查 |
| 性能 | 单请求 P95 ≤ 5s（含 LLM）；PG 查询 P95 ≤ 100ms | 基准脚本（联调周建立基线） |
| 数据安全 | 每日备份成功；每阶段 ≥ 1 次恢复演练 | 备份/恢复日志 |

### 3.3 落地验证（M5 强制关卡）

| 指标 | 目标值 |
|---|---|
| 真实使用时长 | 连续 2 周真实学习使用（非脚本） |
| 完整学习会话数 | ≥ 10 次（诊断→辅导→复习闭环） |
| 真实问题修复 | 依据使用数据修复 ≥ 3 处缺陷/体验问题 |
| 指标面板有数据 | 仪表盘展示真实使用趋势（非空数据） |

## 4. 测试策略

| 层 | 内容 | 执行时机 |
|---|---|---|
| 单元测试 | 状态机转移、图算法、BKT 更新、纯度规则、调度计算 | 每次提交（pytest） |
| 集成测试 | 领域包加载→诊断→辅导→溯源端到端（mock LLM） | 每阶段冻结点 |
| 回归测试集 | 20 题引导纯度 + 诊断根因验证集（真实 API） | 每次变更后自动跑 |
| 故障注入 | 断网/超时/限流下的降级与恢复 | 联调周 |
| 恢复演练 | pg_restore 恢复全量数据 | 每阶段 ≥ 1 次 |

## 5. 风险与应对

| 风险 | 概率/影响 | 应对 |
|---|---|---|
| 通用引擎陷阱：抽象过度、无真实用户 | 高/高 | "先领域后抽象"原则；M5 真实使用是强制关卡 |
| 领域包质量不足（图谱/题目标注） | 高/中 | 严格限定单章节规模；人工校验后才入库；LLM 标注只作初稿 |
| 引导纯度长期不达标 | 中/高 | 回归测试集 + 自检层双保险；评估数据沉淀可支撑微调 |
| LLM API 不稳定/限流 | 中/中 | LiteLLM 多供应商路由 + 故障注入验证降级 |
| 内存不足（16GB） | 低/高 | 内存预算表为硬约束；每周检查实际占用 |
| Docker 环境未整改 | 确定发生/中 | 00-环境搭建.md 第 3 节整改清单为开工前提 |
| 单人超载导致范围蔓延 | 高/中 | 三层边界表 + 冻结点机制：超期先砍范围 |
| 效果难以量化（学习成效） | 中/中 | 用使用频次/完成率/掌握度演化/引导纯度替代成绩指标 |

## 6. 完成定义（Definition of Done）

一个版本判定"完成"，必须同时满足：
1. 全部量化硬指标达标（第 3 节），有测试/审计证据
2. 通过全部冻结点验收与联调周
3. 一键部署可用，备份/回滚演练通过
4. M5 真实使用验证完成（真实数据 + 修复记录）
5. 文档齐备（架构/领域包接入指南/ADR/部署手册/README）
