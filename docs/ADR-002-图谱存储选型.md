# ADR-002：知识图谱存储用 PostgreSQL JSONB（弃 Neo4j）

> 状态：**已接受（2026-08）** · 关联：docs/02 §1 决策 2、docs/03 §2.2、docs/04 决策 2

## 背景

知识图谱需要存节点（知识点：难度/重要度/错误模式/前置依赖）与边（依赖关系），且要支持溯源（依赖链回溯）、路径规划（拓扑序）。当时候选：Neo4j（图数据库）vs PostgreSQL JSONB + 应用层图算法。

## 决策

**PostgreSQL JSONB 存储图谱数据 + 应用层图算法**（BFS 溯源、拓扑路径规划）。图谱数据来源是**领域包**（文件加载，`domain/loader.py`），PG 只存用户学习状态（mastery/events），图谱本身按需从领域包加载。

架构纪律：`domain/loader.load_pack()` 是图谱访问的唯一入口——**存储可替换**（PG JSONB ↔ 文件 ↔ 未来图数据库），上层引擎不关心来源。

## 为什么

1. **规模**：章节级图谱 30-50 节点、100+ 题，无需图数据库的分布式能力
2. **内存**：Neo4j JVM 常驻 3-5GB，本机 16GB 内存跑不动（00-环境搭建 4 节内存预算为硬约束）
3. **一致性**：图谱与用户状态同库，无跨系统同步问题
4. **可替换性**：loader 抽象保证未来节点规模暴涨时可平滑迁移（04 后置项"pgvector/图数据库"触发条件即规模 > 5000）

## 后果

- 正面：单库简单、内存达标、溯源/路径算法用 BFS/拓扑序直接实现（F3 溯源一致率 100%）
- 代价：超大图（>5000 节点）时应用层算法性能受限——触发条件明确，达标前不引入图数据库
- 迁移路径：loader 接口不变，换存储实现即可（已由 M4r18 验证"图谱存储可替换"勾选确认）

## 验证

- 溯源根因一致率 100%（F3）
- 图谱数据全部来自领域包、无硬编码（架构检查单 ✓）
- 领域包加载 fast-fail schema 校验（loader.py）
