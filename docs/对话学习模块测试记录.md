## 验证通过的链路

- 诊断：创建返回题目 → choice 判题 → 答满 qcount → done + completed → 薄弱点总结
- 辅导：创建返回题目 → 判题（答对/答错+正确答案反馈）→ identify→hint→verify→变式 全状态流转
- 变式题生成（id 带 v 前缀）与快照恢复（#999 验证题目卡/选项/提交按钮渲染）
- 会话恢复：原题会话、变式会话均正常渲染作答区

## 已知边界（非 bug，设计如此）

1. **open/blank 题非数字文本答案 → indeterminate**："请直接输入你的答案"——规则兜底无法判定文本，需 LLM 判题（有 key）或有效答案
2. **变式题 answer 不返回前端**：`_question_to_dict` 不含 answer（防作弊），正确
3. **IDENTIFY 态答对 → hint 而非直接 verify**：状态机设计（识别错误后先提示再验证）
4. **辅导 done 路径**：需答对原题+变式题，变式答案无法脚本化获取——学生真实答对即完成（逻辑已由单元测试覆盖：`test_tutor_orchestrator.py` 14 个测试）
5. **答非法选项（如 "Z"）→ indeterminate 分支**：correct=null，前端按无判题处理（边界输入）
