# AdaptTutor 生产部署指南

> 目标：在 Linux 云服务器上用 Docker Compose 一键跑起 **PostgreSQL + 后端 API + 前端 Web + 监控面板（Portainer/Uptime Kuma）** 五服务。
> 前端 `http://<服务器IP>:3000`，后端 `http://<服务器IP>:8010`（浏览器直连，无需 nginx）。
> 有域名后可在前面加 nginx/certbot 做 HTTPS（见文末「后续：域名与 HTTPS」）。

---

## 1. 前置准备

- 云服务器（Linux，建议 2C4G 起），安装 Docker + Compose 插件：

```bash
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker
docker compose version   # 应输出 v2.x
```

- 防火墙/安全组放行 **3000**（前端）与 **8010**（后端），如需 SSH 保留 22。

## 2. 拉取代码

```bash
git clone https://github.com/echo804/AdaptTutor.git
cd AdaptTutor
```

## 3. 生成密钥与生产配置

```bash
python3 backend/scripts/gen_prod_secrets.py    # 生成 backend/.env.production（强密钥）
```

随后编辑 `backend/.env.production`：

| 配置 | 说明 | 建议 |
|---|---|---|
| `DATABASE_URL` | compose 内网直连，一般不用改 | — |
| `POSTGRES_PASSWORD` | PG 密码（compose 环境变量，默认 `adapt_prod_pw`） | **必须改** |
| `LITELLM_API_KEYS` / `MODEL_ROUTING` | 系统级 LLM key（可选；用户自配 key 不依赖） | 按需填写 |
| `API_KEY_ENC_KEY` / `JWT_SECRET` | 已由脚本生成，勿改 | — |
| `INVITE_ONLY` | 邀请码注册 | 上线期建议 `true` |

> `.env.production` 已被 `.gitignore` 忽略，**不会入库**。

## 4. 构建并启动

```bash
# 构建时注入浏览器侧访问的后端地址（改成你的服务器 IP）
export NEXT_PUBLIC_API_BASE=http://<服务器IP>:8010
docker compose -f docker-compose.prod.yml up -d --build
```

首次启动后端容器会自动把镜像内置领域包（数学/大模型/英语）同步进持久卷。

## 5. 验证

```bash
docker compose -f docker-compose.prod.yml ps          # 三服务 healthy/Up
curl http://localhost:8010/healthz                    # {"ok":true,...} + PG 连通
# 浏览器打开 http://<服务器IP>:3000 → 注册/登录 → 开始诊断
```

## 6. 监控面板（Portainer + Uptime Kuma）

compose 已内置两个免费监控面板（M6.1），`up -d --build` 后自动随栈启动。

**端口与访问**（防火墙放行 `3001`、`9443`）

| 面板 | 地址 | 用途 |
|---|---|---|
| Portainer | `https://<服务器IP>:9443` | 容器运维：五容器状态/日志/一键重启 |
| Uptime Kuma | `http://<服务器IP>:3001` | 可用性探活：服务心跳图表 + 宕机通知 |

**首次配置**

1. **Portainer**：浏览器打开 `https://IP:9443` → 创建管理员账号 → Get Started → 选本地环境 → 即可看到 `adapttutor-prod-*` 各容器的状态/日志/重启按钮。
2. **Uptime Kuma**：打开 `http://IP:3001` → 创建账号 → Add New Monitor：
   - 前端：`http://<服务器IP>:3000` 或容器内 `http://web:3000`（间隔 60s）
   - 后端健康：`http://<服务器IP>:8010/healthz` 或容器内 `http://api:8010/healthz`，期望关键词 `ok`
   - ⚠️ 容器内探活注意：Kuma 运行在容器里，**`localhost` 指向 Kuma 自己**——同栈服务用 compose 服务名（`web`/`api`），跨主机用宿主机 IP；本地演示可用 `host.docker.internal`
   - 通知渠道支持 90+ 种（Telegram/邮件/钉钉/Server酱等），在 Notifications 里配置

**日常三命令**

```bash
docker compose -f docker-compose.prod.yml ps                # 五容器状态（Up/Healthy）
docker compose -f docker-compose.prod.yml logs -f api       # 实时看后端日志
docker stats                                                # 实时资源占用（CPU/内存）
```

**服务宕机自动恢复**：compose 已设 `restart: unless-stopped`——崩溃自动拉起，无需人工；只有反复崩溃才需要去 Portainer/日志排查。

## 7. 数据备份与恢复

**备份**（手动或 cron）：

```bash
# 服务器上（容器名/目录与 compose 一致时直接跑）
BACKUP_DIR=/app/backups PG_CONTAINER=adapttutor-prod-pg PACKS_DIR=/app/domain_packs ./scripts/backup.sh

# 每日 02:30 自动备份（crontab -e）
30 2 * * * cd /path/to/AdaptTutor && BACKUP_DIR=/app/backups ./scripts/backup.sh >> /var/log/adapttutor-backup.log 2>&1
```

**恢复**（服务器上新装/故障恢复）：

```bash
# 1) 恢复 PG（容器就绪后）
docker exec -i adapttutor-prod-pg pg_restore -U adapt -d adapttutor -Fc --clean < adapttutor_pg_YYYYMMDD_HHMMSS.dump
# 2) 恢复领域包（覆盖挂载卷）
tar -xzf adapttutor_packs_YYYYMMDD_HHMMSS.tar.gz -C /app/domain_packs --strip-components=1
# 3) 重启 API 使其重新加载
docker compose -f docker-compose.prod.yml restart api
```

**从本地迁移到服务器**（Windows 本地 → 服务器）：本地执行同一 `scripts/backup.sh`（容器名 `adapttutor-postgres`），把生成的 `.dump` + `.tar.gz` scp 到服务器，按上面恢复步骤操作。

## 8. 更新部署

```bash
git pull
export NEXT_PUBLIC_API_BASE=http://<服务器IP>:8010
docker compose -f docker-compose.prod.yml up -d --build
```

## 9. 常见问题

| 现象 | 处理 |
|---|---|
| `api` 容器反复重启 | `docker compose logs api` 看启动错误；常见：`.env.production` 密钥为空/格式错 |
| 前端页面能开但接口 404 | 构建时 `NEXT_PUBLIC_API_BASE` 没设或设错 → 重新 build |
| 8010/3000 被占用 | 修改 `docker-compose.prod.yml` 的 `ports` 映射 |
| 忘记 PG 密码 | 见 `.env.production` 的 `POSTGRES_PASSWORD`，与 compose 环境变量一致即可 |

## 10. 后续：域名与 HTTPS

有域名后，在服务器加 nginx 反向代理（前端 3000、后端 8010 走 `/api` 前缀转发），用 certbot 签发证书：

```nginx
server {
    listen 443 ssl;
    server_name your.domain.com;
    # certbot 自动管理证书路径
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:8010/api/;
    }
}
```

同时把 `NEXT_PUBLIC_API_BASE` 改为 `https://your.domain.com` 重新构建。
