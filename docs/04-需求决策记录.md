## 1. 第二层：技术决策（6 项）

### 1.1 流式通道 → WebSocket
- 对话为双向（学生发言 + 老师流式回复），SSE 单向需 REST+SSE 双连接，复杂度更高。
- FastAPI 与浏览器端均原生支持；自带心跳可判断线，配合"会话可恢复 100%"硬指标。
- 03 文档 5.1 表格中"SSE 可选"为笔误，以 5.4"流式对话用 WebSocket"为准。

### 1.2 图谱前端库 → @xyflow/react (v12)
- `react-flow-renderer` 为 v11 旧名，已迁移至 `@xyflow/react`，新项目不引入旧包。
- 实施注意：需 `dynamic(..., { ssr: false })` 动态导入，规避 Next.js SSR 报错。
- 该库同时支持**展示与编辑**，是可视化领域编辑器的技术基础。

### 1.3 状态机↔LLM↔自检时序（核心原则：LLM 不参与状态决策）
1. 状态机收到学生消息 → 按转移矩阵**确定性**决定下一步动作（如"生成最小提示"）。
2. 调 LLM 生成候选文本 → 自检层规则判定（禁止句式清单 + 纯度规则）→ 不过则重生成（≤2 次）。
3. 仍不过 → 降级为**模板话术**；最终文本 + purity_score 返回，状态机据此完成流转。
- 效果：状态机可单测全覆盖（硬指标）；LLM 不确定性被隔离在内容层；可回滚。
- **学生作答正确性判定分级**（文档未写，此处补齐）：
  - 选择题 / 填空题 → 规则判定（标准答案 / 规范化比对），零 LLM 依赖；
  - 解答题 → LLM 判题 + 置信度，低置信度时状态机转"追问澄清"，不硬判。

### 1.4 领域包生产方式
- **图谱骨架（30-50 节点）人工产出**：前置依赖关系错误全盘皆错，是领域包核心资产；LLM 仅辅助生成节点描述/错误模式候选。
- **题目 LLM 批量生成初稿**（题干/选项/错误模式/步骤→节点映射）→ 人工逐题校验后入库（对齐 02 风险表"LLM 标注只作初稿"）。
- **题目自创，不抄教辅**（版权）；100 题规模可控。
- 所有入库数据必须通过领域包加载器 schema 校验（M1 验收项）。

### 1.5 算法参数初始值（全部参数化，M5 用真实数据校准）
- BKT 文献常见默认：`P(L0)=0.3, P(T)=0.05, P(G)=0.2, P(S)=0.1`（M1 KST 简化版先用确定性估计）。
- 诊断终止条件对齐硬指标：**根因置信度 ≥ 阈值 或 达到 15 题上限**。
- 遗忘曲线：简单指数衰减，`mastery_p` 按衰减率递减，复习时间窗 = f(当前掌握度, 衰减率)。
- **约束：数值全部进领域包配置文件，引擎只读配置不写死**——M5 调参不动代码。

### 1.6 图谱加载 → 启动时全量加载进内存
- 30-50 节点为 KB 级数据，启动加载成本可忽略；拓扑排序、依赖链回溯、路径规划全在内存执行。
- 领域包为"不可变数据 + 版本号"，变更走版本重载。
- 掌握度等**动态**数据仍走 PG，两者不混。
- 加载器走 repository 接口，未来换图数据库只换实现（架构纪律）。

## 2. 第三层：需求决策（8 项）

### 2.1 用户与登录（修订 02 计划）
- **有登录 + 密码**。演进路线：本地私家用 → 云部署邀请制公开。
- **注册形态：邀请码制**——管理员生成邀请码，凭码注册；控制规模与成本，避免垃圾注册。
- **免费，不做计费**；**所有用户平权为学习者**，无角色分级、无管理员后台。
- 实现：`users` 表 + bcrypt/argon2 哈希 + JWT（`Authorization: Bearer`）；不引入 Keycloak/Auth0 等重型组件。
- 登录安全强化（防爆破/验证码/密码重置/HTTPS）为**上云前置项**（见第 6 节）。
- 连带修订：02 计划 1.2"Must Not"——"权限系统/多租户/计费"改写为"邀请制多用户、无角色分级、无管理员后台；多租户隔离与计费不做"。

### 2.2 数据留存
- 历史数据（事件流/评估/消息）**永久保留**，是溯源与评估的唯一依据。
- 掌握度**不自动重置**；提供"重新诊断"手动重置入口。
- "备份保留 7 天"为防灾难的滚动快照，与数据本体永久保留不冲突。

### 2.3 会话形态
- 无固定时长，按学习单元自然结束（诊断=收敛、辅导=目标节点达成、复习=到期题目清空）。
- 断线/退出可恢复：状态机状态在 PG，重连从断点继续（对齐"会话恢复 100%"）。
- 前端提供"结束会话"按钮；预期节奏：每天 1 次辅导 + 到期复习，单次 15-30 分钟。

### 2.4 题型 → 三题型分级
| 题型 | 判题方式 | 定位 |
|---|---|---|
| 选择题 | 规则判题（标准答案），零歧义 | 诊断阶段主力 |
| 填空题 | 答案规范化后规则比对 | 辅导/复习使用 |
| 解答题 | LLM 判题 + 置信度，低置信转"追问澄清" | 苏格拉底对话核心 |
- 理由：只做选择题会让苏格拉底对话退化为"四选一猜谜"；全自由文本判题不可靠，故分级。

### 2.5 内容边界 → 人教版七年级上 + 下
- 七年级上：一元一次方程（解法 + 应用题）。
- 七年级下：二元一次方程组（代入/加减消元 + 应用）、一元一次不等式（性质/解集/数轴）、一元一次不等式组（交集/应用）。
- **含参方程/不等式（分类讨论）列为后置**，不进本期图谱。

### 2.6 失败降级（LLM 不可用）→ 三层
1. LiteLLM 故障转移切备用模型（对齐降级成功率 ≥ 99% 硬指标）。
2. 全部模型失败 → **模板话术模式**：预置提示模板 + 题库兜底，诊断/复习可继续，辅导只给固定引导话术。
3. 前端明确提示"离线模式，部分功能不可用"，不假装正常。

### 2.7 报告与仪表盘
- **只给学习者本人看**：诊断报告（薄弱点 + 根因链 + 推荐路径）、进度仪表盘（掌握度演化时间线 + 到期复习 + 学习时长）、错题溯源视图（图谱高亮根因路径）。
- 家长/老师视角报告（PDF 导出）**后置**，触发条件 = 出现第二使用者。
- 数据全部来自 PG 现有表，无新存储。

### 2.8 部署与访问（本地先行 → 云部署演进）
- **本期**：本机 `localhost` + 局域网访问（docker compose 三服务；已有登录，局域网可信可用）。
- **演进**：本地验证通过后云部署（邀请制公开）。上云前置：HTTPS + 域名 + nginx 反代、注册/邀请码流程、防爆破、云备份（异地/对象存储）。
- **compose 拆分**：本期约定 `docker-compose.local.yml`（开发）与 `docker-compose.prod.yml`（上云时加 nginx/HTTPS/卷策略）结构，**本期只实现 local 版**。
- 16GB 本地内存约束在云端可放宽（按云规格），"能砍则砍"原则不变。

### 2.9 LLM API key：用户自主配置，强制自配（新增）
- **原则**：各用户必须在设置页配置自己的 API key（多供应商：DeepSeek/Qwen/GLM 各一格）才能使用 AI 功能；成本归各用户。
- **强制自配（无全局兜底）**：未配置有效 key 的用户**不可使用涉及 AI 的主要功能**，仅可浏览页面 + 简单非 AI 交互（见下）。
- **存储**：新增 `user_api_keys` 表（user_id, provider, encrypted_key, created_at, updated_at）；**Fernet 对称加密入库**，加密密钥 `API_KEY_ENC_KEY` 放 .env，与 key 本身分离。
- **界面**：设置页掩码显示（`sk-****abcd`），不可回读；保存时可测试调用验证有效性。
- **失效处理**：已配 key 的用户在 key 失效/欠费时，按 2.6 三层降级处理（模板话术模式等），不自动切换他人 key。
- **全局 `LITELLM_API_KEYS` 语义**：仅用于开发/测试/系统内部用途，**不作为用户兜底**。
- **安全**：key 永不入日志（沿用 00 文档脱敏规则）；前端不可读回明文。

**未配 key 体验（产品行为）**：
- **可用**：图谱浏览（拖拽/缩放/点节点看说明与依赖关系）、查看已生成的报告与历史、设置页（配置 key/改密码）、账号管理、主题切换。
- **不可用**（AI 功能入口置灰 + 点击引导去配置）：诊断、辅导、复习会话、判题、图谱"开始学习/做道题试试"等一切需 LLM 的操作。
- 登录后仪表盘显示引导横幅："配置你的 API key 后即可开始诊断与辅导"。

## 3. 新增需求：可视化领域编辑器（进本期）

- **定义**：界面可视化创建/编辑领域包——图谱节点/边（React Flow 编辑能力）、题目录入、校验反馈、导入导出。
- **验收**：编辑器产出的领域包能被引擎"零改代码"消费（与手写目录走同一 schema 校验）。
- **排期**：选 **A——总周期延长至 13-14 周**，不砍非核心范围（02 计划 12 周 → 13-14 周）。
- **时序约束**：编辑器在**引擎闭环跑通之后**实施（M2/M3 后），先用内置领域包 1 稳定引擎接口，编辑器才有参照物。
- 影响面：新增前端页面 + 后端领域包写入 API + 校验工具链；新增里程碑或并入既有阶段（实施计划时细化）。

## 4. 产品形态：本地网页优先，软件化不锁死

- **本期**：纯网页（localhost + 局域网），Docker 三服务。
- **软件化路径**（按需后置，当前零成本）：
  1. **PWA 安装**：独立窗口 + 任务栏图标，Chrome/Edge"安装应用"即得，零内存、零打包——首选；
  2. **Electron 壳**：真桌面软件，但每个实例 +200-400MB 内存、安装包 100MB+，违背 16GB 预算；
  3. **Tauri 壳**：轻量，但需 Rust 工具链（本机未装）。
- 前后端分离架构下加壳只包前端，后端 Docker 不动，**不锁死**。
