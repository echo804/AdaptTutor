## 第 1 批 · 辅导闭环真的能用（T1，最先做）

> 这一批决定"产品是不是产品"：引导能进行下去、判得准、变式题有解、答案不泄露。

### 1.1 【最大】辅导页：卡片栈 → 对话流

- **修**：P1-1（答错即死锁）、P1-2（引导语零渲染）、P2-2（`correct=False` 三义混用导致的三条死锁路径）、P2-3（完成语被吞）
- **范围**：第 7 章 **A 刀**，只改 `frontend/app/chat/page.tsx`（1084 行）+ 可能 3 行全局 CSS
- **为什么先做**：用户反馈 #4，已实测复现，是"用现有契约就能修好"的典型——不需要先改后端
- **核心改法**：`closed` 只由 `state === "done"` 或"是否换题"决定，**与 `correct` 无关**

```ts
const judged   = r.correct !== null;              // 只决定"要不要显示判词"
const newQ     = r.question;
const sameQ    = !!newQ && !!question && newQ.id === question.id;
const pushed   = !!newQ && !sameQ;               // 换题 → 上一题终结
const finished = r.state === "done" || r.done === true;
setQuestion(newQ ?? (finished ? null : question));
setClosed(finished || pushed || !newQ);          // ← 死锁在这里被消除
```

- **状态模型替换**：`cards/currentIdx/flipped` → `msgs / question / closed / unlocked / gateOpen / qIndex / draftMode`
- **恢复会话**：改调 `GET /sessions/{sid}/messages`（后端已存在，此前前端从未调用）重建对话流
- **临时债**（第 2 批必须删）：靠 `^[✓✗]` 前缀切分"判题行/引导语"，代码里会标注
- **验收**：第 7.6 节 V1–V10 十条断言，用 Playwright 打真实 dev server

### 1.2 【次大】判题规则层三条误判

- **修**：P1-3、P1-4、P1-5
- **文件**：`backend/app/engine/evaluator.py`
- **影响面**：144 道填空/解答题中 119 道（83%）答案是文本型，都可被子串规则误判

| 编号 | 问题 | 实测 | 修法 |
|---|---|---|---|
| P1-3 | `nu in na` 双向包含 → 残缺答案判对 | `固化成历史节点` vs `历史` → 判对 | 删掉 `nu in na` 方向，或加最小长度/词数比例门槛 |
| P1-4 | 数字只查"是否都出现过" → 无关数字即满足 | 答案 `5/6` 答 `6/5` → 判对；`x=6,y=4` 答 `x=4,y=6` → 判对 | 改**有序/带位置**的数字比较，至少要求数字序列一致 |
| P1-5 | 规则判对即短路 LLM → 误判不可纠正 | `if rule is not None and rule.correct: return rule` | 规则判对时对长答案仍走一次语义校验 |

### 1.4 变式题数学自洽性 ✅ 已完成（2026-10-06）

- **修**：P1-7、P1-8、P4-10 · **文件**：`backend/app/engine/variant_generator.py`（重写）、`tutor_orchestrator.py`、`tests/test_scheduler_variant.py`
- **问题**：choice 分支平移了选项数值却保持答案字母不变 → 选项里没有正确答案

```
原题  -3-5=?  答案 -8
变式  -6-8=?  （真值 -14）选项 [5,-11,11,-5]，答案字母仍指 B = -11  ← 无解
```

- **实测范围比清单更大**：**自洽率 0%**（可机械判定的 30 道 choice 变式全部无解）。
  且不只 choice —— blank 分支同样错：`当 $x=2$ 时 $3x+1$`（答案 7）平移后题干是
  `x=3, 4x+2`（真值 14），答案却被写成 8。
- **修法**：① 内置安全算式求值器（AST 白名单，Fraction 精确算）；
  ② **整题重算** —— 解出新题干真值后，用各选项相对真值的偏移重建选项，
  干扰项的错误模式（符号错/优先级错）原样保留，答案字母天然不变；
  ③ `verify_variant()` 独立重算终检：真值必须唯一命中答案，选项不得重复；
  ④ **解不出真值就拒发**（`ok=False`），编排层退回换题/复习，绝不下发无解题；
  ⑤ `generate_batch` 不再 `zip` 静默截断（P4-10：235 在任何路径下都产生不了），
  长度不匹配直接报错，单 seed 广播到全部题。
- **顺带修掉两个自查出来的问题**：
  - `delta` 只有 1-5 五档 → 同题 seed=1/3/4 全撞成 `$-5-7=?$`，变式自己先重复了。放宽到 2-9。
  - 编排层生成变式后没记入 `_verify_used` → 补上（上一轮的去重只对题库题生效）。
- **验收**：
  - 生成的变式题 **100% 自洽**（不再是 0%）；覆盖率 10.6%（数学包），概念/文本题 0% 且全部拒发
  - 端到端 15 轮连续答题：**0 无解题、0 重复、0 卡死**
  - `pytest` 135 passed（基线 121，+14 为新增变式测试）；`git stash` 对比 7 failed 完全一致 → 零回归
- **未做**：LLM 出题路线（04 决策的另一条）。覆盖率低是如实反映，不是回归。
