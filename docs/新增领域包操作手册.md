# 新增领域包操作手册（M4r8）

> 目标：让「大模型应用开发」之外的任何领域都能低成本接入——**AI 生成初稿 + 人工校验**，
> 引擎零改代码（`03-项目架构.md`：接入新领域 = 新增一个目录）。

## 四步流程

### ① 准备素材文档

- 任意数量的 Markdown 文档，按**主题子目录**分组（如 `llm/`、`rag/`、`agent/`）
- 每个主题目录名会映射为节点 id 前缀（`llm→l`、`rag→r`、`agent→a`、`tools→t`、`overview→o`）
- 文档建议带标题 frontmatter；正文越结构化（要点/对比/示例）生成质量越高
- 参考：`D:\codexproject\codexproject\HireMind\xiaolinnote_knowledge`（78 篇，已用于 llm_app_dev）

### ② AI 生成初稿

```powershell
cd backend
& "D:\codexproject\codexproject\AdaptTutor\.venv\Scripts\python.exe" -X utf8 scripts/new_pack_ai.py `
  --source "D:\你的素材目录" `
  --out "..\domain_packs\你的包id"
```

- 包 id：小写字母/数字/下划线，如 `my_domain`
- 脚本自动：分批调 LLM（qwen-turbo，用户 key）→ 提炼图谱节点/前置边 → 生成三档题
  （choice/blank/open）→ 字段规范化 → schema 校验 → 输出 `审阅清单.md`
- key 来源：自动取 `user_api_keys` 表（优先 `ye` 等真实用户，跳过测试占位符）；
  也可 `--user-key sk-xxx` 显式传入
- LLM 模型路由在 `backend/.env` 的 `MODEL_ROUTING`（当前 `dashscope/qwen-turbo`，
  百炼平台免费额度模型）

### ③ 人工逐题校验（关键）

打开 `domain_packs/<包id>/审阅清单.md`，逐题核对：
- **事实正确性**：答案是否与文档一致、无编造数字
- **选项唯一性**：choice 题答案唯一、干扰项合理
- **难度分级**：difficulty 0.3-0.75 是否与题型匹配
- **知识点映射**：`step_node_map` 是否指向正确节点（错题溯源依赖它）
- 改完 JSON 后运行校验：

```powershell
& "D:\codexproject\codexproject\AdaptTutor\.venv\Scripts\python.exe" -X utf8 scripts/new_pack_ai.py --dry
```

### ④ 上线

- 领域包目录放好后，前端顶栏「领域选择器」自动出现新领域（`GET /api/v1/domains` 扫描）
- 用户切换即进入该领域的独立学习空间：诊断/辅导/图谱/掌握度/错题全部按领域隔离
- 如需默认领域调整：`backend/.env` 的 `ACTIVE_DOMAIN_PACK`

## 领域包目录结构

```
domain_packs/<包id>/
├── pack_manifest.json      # {id, version, subject, engine_version}
├── knowledge_graph.json    # nodes[{id,name,difficulty,importance,error_modes}] + edges[{from,to,type:prerequisite}]
├── questions.json          # 题目（三档题型，含 answer/options/error_modes/step_node_map/tags[来源]）
├── diagnostic_rules.json   # 诊断策略 + BKT 参数 + 终止条件
├── assessment_config.json  # 纯度/掌握阈值
└── 审阅清单.md             # 人工校验清单（不入引擎）
```

## 注意事项

- **节点 id 前缀**：各主题子目录映射固定前缀，跨批自动续号；不要手工改前缀
- **边只画前置依赖**：`from` 是 `to` 的前提，错画会污染溯源/路径
- **数据隔离**：每个领域的掌握度/错题独立存储（`mastery_states.pack_id`），切换不串
- **审阅是质量的唯一保障**：AI 初稿必须人工过一遍再投入使用
