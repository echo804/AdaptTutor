# AdaptTutor —— 通用学习引擎 + 领域包

> 一个领域无关的自适应学习引擎：知识图谱为骨架、苏格拉底式状态机对话为交互，提供"诊断 → 路径规划 → 引导辅导 → 错题溯源 → 遗忘调度复习"的完整学习闭环。学科内容以"领域包（Domain Pack）"接入，不绑定任何具体学科。

**定位声明**：不做商业化，不做 demo。追求成熟完整、真实可落地——系统能被长期使用、数据不丢、效果可验证、出问题可修。

## 关键决策摘要（V1.0 → V2.0）

| # | 决策 | 结论 | 一句话理由 |
|---|---|---|---|
| 1 | 项目形态 | **通用学习引擎 + 领域包**（先领域后抽象） | 领域作为配置接入，引擎可复用、可验证，避免"平台陷阱" |
| 2 | 图谱存储 | **PostgreSQL JSONB + 应用层图算法**（弃 Neo4j） | 章节级图谱无需图数据库；Neo4j JVM 常驻 3-5GB，16GB 机器跑不动 |
| 3 | 向量检索 | **标签过滤**（弃 Qdrant，预留 embedding 字段） | 数百题规模无需向量检索 |
| 4 | 任务队列 | **FastAPI 后台任务**（弃 Celery + Redis） | 单机无分布式诉求 |
| 5 | 对话控制 | **自研四态状态机**（弃 LangGraph） | 确定性、可测试、可回滚；精确控制"不直接给答案" |
| 6 | 可观测性 | **结构化日志 + trace_id**（OTel/LangFuse 后置） | 单机场景先日志后仪表盘 |
| 7 | 前端 | Next.js + React Flow + KaTeX（弃白板） | 图谱可视化 + 公式渲染是刚需，白板是非核心复杂度 |
| 8 | 差异化 | **工程价值**：数据一致性 / 图谱可维护性 / 质量回归防线 | 不商业化，差异化回归为"系统能否长期真实可用" |
| 9 | 用户与认证 | **邀请码注册 + JWT + 用户自配 API key**（强制自配，无全局兜底） | 成本归各用户；未配 key 仅可浏览页面 |
| 10 | 演进 | **本地先行 → 云部署邀请制公开**（免费/平权学习者） | 本地验证后上云；上云前置项见 04 第 6 节 |

**核心约束**：本机 16GB 内存，服务常驻预算 ≤ 7GB（详见 docs/00-环境搭建.md 第 4 节）。

## 首个领域包

**初中数学·方程与不等式**（内置，作为引擎验收试验台）
- 知识图谱：30-50 个知识点（难度/重要度/错误模式/前置依赖）
- 题库：100+ 题（知识点标签/选项错误模式/解题步骤→节点映射）

接入新学科 = 在 `domain_packs/` 下新增一个目录（零改引擎代码），或使用**可视化领域编辑器**（M6，React Flow 拖拽建图 + 题目录入，与手写目录同一 schema 校验）。
